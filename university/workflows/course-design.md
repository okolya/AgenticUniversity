# Course Design Workflow

Owner: appointed Dean of the Faculty.

Purpose: create or revise the stable Course direction and Module framework without prematurely authoring detailed learning content.

1. Dean identifies the Faculty need and the Course purpose.
2. Dean defines the Course name, direction, target outcome, target competencies, and prerequisites.
3. Dean may request subject proposals from appointed Lecturer(s), measurable competency input from Learning Analyst, practical capability input from Laboratory Specialist, and examination perspective from Examiner.
4. When current external knowledge matters, contributors may use `research-materials`; sources inform the design but do not own it.
5. Dean defines the Module framework: Module names, value/purpose, broad competency outcomes, ordering/dependencies, and Course-level Success Criteria.
6. Dean checks that Modules represent distinct educational value rather than arbitrary topic buckets.
7. Dean approves and writes the canonical Course definition under `university/courses/` and links it from the Faculty.
8. Detailed Module content is intentionally deferred until Module Entry. It is created/refined just in time from verified Student state, prior learning, current field knowledge, and Course goals.
9. Later revisions preserve the distinction between stable Course architecture and adaptive Module detail.

Academic authority remains with the Dean. Supporting Workers contribute expertise; Skills perform bounded operations; neither owns the Course decision.
