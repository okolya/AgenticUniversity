# Course Entry Workflow

Owner: appointed Dean of the target Faculty.

Course Entry is the decision that ends the pre-course layer. It is distinct
from both the stable public Course framework and entry into a particular
Module.

1. Rector or the responsible Faculty Dean registers the Student for the
   Course's pre-course orientation layer.
2. Dean loads the Course architecture, the relevant Module Entry Contracts,
   permitted Student context, and any existing verified evidence.
3. Dean identifies the smallest unresolved Entry Contract gaps. Already
   demonstrated capability is not automatically retaught.
4. If a gap can be closed by preparation, Dean issues a bounded pre-course
   sequence with target criteria, allowed slots, evidence checkpoints, and a
   stop condition.
5. If independent evidence is needed, Dean sends Contract 1 from
   `assessment-contracts.md` to the appointed Learning Analyst. Lecturer
   prepares bridge Lessons only inside the separate teaching sequence.
6. Learning Analyst builds the assessment through Contract 2, invokes the
   Instructional Assistant through Contract 3, performs the assessment, and
   returns Contract 4. Learning Analyst records permitted evidence in the
   private Student workspace through `update-evidence`.
7. Lecturer returns formative observations separately. Neither Lecturer nor
   Learning Analyst starts Course delivery or chooses the Student's trajectory.
8. Dean decides one of the following:
   - confirm Course Entry and select the first Module Entry route;
   - issue another bounded pre-course bridge where policy permits;
   - defer entry pending a specific independent measurement;
   - choose another Faculty/Course route.
9. Only after Course Entry is confirmed may the Dean open a Module-specific
   coverage plan and create detailed Module Themes under the Module directory.

Pre-course artifacts remain public University material, while the Student's
actual responses, evidence, capacity, and decisions remain in the private
Student repository.
