# Lesson Preparation Workflow

Owner: appointed Lecturer for a lesson introducing new material.

Lesson preparation is format-neutral. The Lecturer selects only the form and
amount of material needed for the outcome; no fixed headings or mandatory
section list should be added when they do not help the learner or expose a
declared criterion.

1. Load the Dean-approved bounded Theme sequence, its current Lesson slot,
   evidence checkpoint, stop condition, Theme outcome, relevant Success
   Criteria, current Student evidence, prior Lesson result, explicitly
   skipped/already-demonstrated criteria, and AI-use policy, together with the
   applicable learning interaction contracts.
2. Define one clear Lesson outcome inside the assigned slot: what the Student
   should understand or be able to do after this learning step.
   State the parent Theme criterion and the prior Lesson result that this
   outcome uses.
3. State the Lesson's new evidence delta: what will be demonstrated now that
   was not demonstrated by the supplied prior evidence. Compare the planned
   task with relevant diagnostics and prior Lesson artifacts. If it repeats
   the same capability with only changed names, values, or wording, stop and
   return it to Dean for a skip or redesign decision.
   State how this delta enables the next Lesson or the Theme checkpoint.
4. Select the smallest coherent content needed for that outcome.
5. Curate external material first where it is high quality and suitable; record source and exact relevant section. Use `research-materials` when needed.
6. Use `author-material` for original explanations, examples, notes, diagrams/specifications, or bridging material that is actually needed.
7. Prepare formative questions/exercises sufficient to expose misunderstanding.
   For executable work, specify the smallest required evidence and state that
   the accepting Worker will inspect and run the code. These are teaching
   checks, not independent verified assessment.
8. If practice is substantial, request a Lab from Laboratory Specialist. If reinforcement/remediation is needed, hand the relevant outcome/gap to Teacher.
9. Deliver/record reusable public learning material where appropriate. Student mastery conclusions remain private Student state.
10. After receiving a Student response, send it through the dual-track process:
   Lecturer evaluates knowledge against the Lesson criteria; Instructional
   Assistant extracts criticism and reviews the complete material.
11. Lecturer decides whether feedback warrants a revision, makes any revision,
    and performs a complete final review of the whole Lesson.
12. Return the prepared Lesson through the material-owner → Instructional
    Assistant review contract before delivery. Do not add Lesson slots, extend
    the bounded sequence, or expand Theme or Module scope from inside a Lesson.
    Student feedback cannot compel a change to Lesson, Theme, Module, Course,
    criteria, or academic authority.

## After Student submission

Submitting the Lesson evidence is a handoff, not the end of the learning
workflow. The Lecturer must:

1. evaluate the demonstrated understanding against the Lesson criteria;
2. acknowledge the Student's material criticism and record a disposition for
   each criticism;
3. identify the next academic action and communicate it to the Student.

The next action is selected from the evidence and the approved Theme frame,
while the bounded sequence still has an assigned slot:

- Lecturer continues with explanation, correction, or the next assigned Lesson
  when the Student needs teaching or the current criteria are sufficiently
  demonstrated;
- Teacher receives a bounded reinforcement/remediation request when a known
  gap needs consolidation rather than new Theme design;
- Laboratory Specialist receives a bounded practical request when practice is
  the missing evidence or capability;
- Learning Analyst receives an independent measurement request only when a
  verified diagnostic or assessment decision requires independent evidence;
- Dean receives a scope, placement, trajectory, or Module-contract question.

The Lecturer must not delegate merely because a submission exists. Delegation
requires a concrete gap, purpose, scope, and handoff. A successful Lesson
submission does not close the public Lesson, Theme, Module, or Course; it moves
the Student and the responsible Worker to the next justified step inside the
  bounded sequence. When the Theme sequence reaches its checkpoint or stop
  condition, the Lecturer returns the accumulated evidence to Dean. Dean then
  confirms Theme completion, opens the next approved Theme, requests a bounded
  correction, or requests independent measurement; the Lecturer does not keep
  generating Lessons while waiting for that decision.
