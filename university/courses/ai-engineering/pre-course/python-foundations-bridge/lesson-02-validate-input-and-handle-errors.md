# Урок 02 — Перетворення та перевірка вхідних даних

## Мета уроку

У попередньому уроці ти запускав програму й спостерігав дві різні причини
помилки: текст `seventy` не можна перетворити на ціле число, а число `110`
не належить дозволеному діапазону оцінок. У цьому уроці ти розділиш ці дві
перевірки в окремій функції та навчишся пояснювати, на якому етапі виникла
помилка.

Це урок про межу між текстовим введенням, числовим значенням і перевіркою
правил. Це не повний курс обробки помилок і не підсумкове оцінювання.

## Очікуваний результат

Після уроку ти маєш уміти:

1. Пояснити, чому `input()` повертає текст навіть тоді, коли користувач
   вводить цифри.
2. Відрізнити помилку перетворення тексту на число від помилки допустимого
   діапазону.
3. Виділити перевірку вхідних даних в окрему функцію `parse_score`.
4. Перевірити звичайне введення, текст без числового значення та число поза
   діапазоном.
5. За повідомленням про помилку визначити, яка перевірка її спричинила.

## Зв’язок із попереднім уроком

У попередньому уроці функція `main` сама виконувала кілька різних кроків: читала текст,
перетворювала його на число, викликала `describe_score` і друкувала результат.
Тепер перетворення та перевірка вхідних даних матимуть окреме місце — функцію
`parse_score`. `main` залишиться простішою, а межа між введенням і логікою
опису оцінки стане видимою.

## Дві різні помилки

### Помилка перетворення

Коли `input()` читає `seventy`, програма отримує текст. `int(raw_score)` не
може перетворити цей текст на ціле число, тому виникає `ValueError` під час
перетворення.

### Помилка правила діапазону

Коли `input()` читає `110`, перетворення на ціле число успішне. Але оцінка
`110` не відповідає правилу `0–100`, тому програма окремо відхиляє це значення.
Це вже не помилка перетворення тексту.

Однаковий тип винятку (`ValueError`) не означає однакову причину. Щоб
зрозуміти причину, дивись на повідомлення та місце, де виник виняток.

## Окрема функція перевірки

Створи файл `lesson02_score.py` і введи цей код:

```python
def parse_score(raw_score):
    try:
        score = int(raw_score)
    except ValueError:
        raise ValueError("score must be a whole number")

    if score < 0 or score > 100:
        raise ValueError("score must be between 0 and 100")

    return score


def describe_score(score):
    """Return a label for a score on a 0–100 scale."""
    if score >= 70:
        return "ready"
    return "keep practicing"


def main():
    raw_score = input("Enter a sample score from 0 to 100: ")
    score = parse_score(raw_score)
    label = describe_score(score)
    print(f"Score {score}: {label}")


if __name__ == "__main__":
    main()
```

Зверни увагу на межі відповідальності:

- `main` отримує текст і передає його до `parse_score`;
- `parse_score` перетворює текст, перевіряє діапазон і повертає ціле число;
- `describe_score` вже не займається текстом, а отримує перевірене число;
- `print` виводить підсумкове повідомлення лише після успішних перевірок.

## Перевірка

Запусти файл із каталогу, де він збережений:

```text
python3 lesson02_score.py
```

Виконай чотири окремі запуски:

1. Введи `72`. Очікуй `Score 72: ready`.
2. Введи `55`. Очікуй `Score 55: keep practicing`.
3. Введи `seventy`. Очікуй повідомлення `score must be a whole number`.
4. Введи `110`. Очікуй повідомлення `score must be between 0 and 100`.

Для кожного запуску визнач, чи дійшла програма до `describe_score` і `print`,
чи зупинилася раніше в `parse_score`.

## Практичне завдання

Самостійно внеси одну зміну до `parse_score`:

> Перед перевіркою порожнього введення явно прибери пробіли на початку та в
> кінці тексту. Окремо відхили порожній результат. Не змінюй правила
> діапазону.

Метод `int()` і без додаткового очищення перетворює текст на кшталт
`" 72 "` на число `72`. Тому `strip()` потрібен у цій вправі не для того,
щоб допомогти `int()`, а щоб окремо перевірити порожній або заповнений лише
пробілами ввід. `strip()` створює текст без пробілів на початку та в кінці;
перевір порожній результат після цього очищення до виклику `int()`.

Перед зміною поясни, де саме має бути виконане очищення тексту. Не переписуй
усю функцію: зміни лише те, що потрібно для цього правила.

Перевір:

- ` 72 ` має бути прийнято як число `72`;
- порожнє введення або `   ` має завершуватися окремим повідомленням про
  відсутність оцінки;
- `seventy` усе ще має завершуватися повідомленням про ціле число;
- `110` усе ще має завершуватися повідомленням про діапазон;
- `55` усе ще має виводити `Score 55: keep practicing`.

Після запуску поясни не лише результат, а й межу відповідальності: яка функція
знає про текст, яка — про число, а яка — про готовність оцінки.

## Межі використання ШІ

Можна попросити ШІ пояснити `try`, `except`, `int`, `ValueError` або показати
різницю між помилкою перетворення та помилкою діапазону. Не проси ШІ виконати
зміну за тебе, створити готове рішення або вигадати результати запуску.
Зміни код самостійно й повідом лише ті спостереження, які справді отримав.

потрібні. Приймаючий Worker сам перегляне код і запустить його для перевірки
звичайної, граничної та помилкової поведінки.
