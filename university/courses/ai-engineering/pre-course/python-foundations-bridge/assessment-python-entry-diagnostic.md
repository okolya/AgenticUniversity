# Незалежна діагностика — базова Python-компонента

## Призначення

Це обмежена діагностика для незалежного вимірювання базових Python-компетенцій
перед рішенням про вступ до курсу та визначення першого модуля. Це не урок і
не підказка до розв'язання.

Діагностику проводить аналітик навчання (Learning Analyst) окремо від
викладання цього матеріалу.

## Що перевіряється

- створення та запуск невеликої Python-програми;
- поділ задачі на функції й послідовні кроки;
- робота з текстовим введенням, перетворенням і перевіркою даних;
- розрізнення помилки перетворення та помилки діапазону;
- читання фактичної поведінки програми й коротке пояснення її меж.

Діагностика самостійно не визначає вступ до курсу або модуля, не
перевіряє Git, залежності, конфігурацію чи секрети та не визначає наступну
навчальну траєкторію.

## Практичне завдання

Створи файл `diagnostic_temperature.py` у приватному робочому просторі
студента. Напиши програму, яка отримує температуру як текст.

Програма має містити такі функції:

- `parse_temperature(raw_value)` — обробляє текст, перетворює його на ціле
  число та перевіряє діапазон від `-30` до `50`;
- `describe_temperature(temperature)` — повертає `cold`, якщо значення менше
  за `10`, і `comfortable`, якщо значення дорівнює `10` або більше;
- `main()` — отримує введення, викликає попередні функції та друкує результат.

Для успішного введення результат має мати такий вигляд:

```text
Temperature <число>: <опис>
```

Помилка перетворення та помилка діапазону мають залишатися різними випадками.
Програма не повинна мовчки приймати значення поза діапазоном.

## Обов'язкові запуски

Запусти програму окремо для кожного значення:

1. ` 8 ` → `Temperature 8: cold`;
2. `22` → `Temperature 22: comfortable`;
3. `warm` → помилка перетворення;
4. `70` → помилка діапазону.

## Мінімальна здача

Поверни лише:

- шлях до файлу та команду запуску;
- короткий фактичний результат для чотирьох запусків;
- одне-два речення про відповідальність `parse_temperature`,
  `describe_temperature` і `main`;
- тип помилки та фінальне повідомлення для випадків `warm` і `70`;
- коротку інформацію про використання дозволеної документації або ШІ, якщо
  це передбачено режимом роботи.

Не переписуй повний traceback, повний запис термінала або довгий опис кожного
кроку. Форма відповіді не є критерієм оцінювання.

## Приймання роботи

Приймаючий аналітик навчання (Learning Analyst):

1. переглядає фактичний файл `diagnostic_temperature.py`;
2. запускає його самостійно та перевіряє всі чотири випадки;
3. порівнює фактичну поведінку коду з коротким описом студента;
4. ставить одне коротке уточнювальне питання або просить малу контрольовану
   зміну, якщо потрібно перевірити самостійне розуміння коду.

Показаний результат без робочого файлу не є достатнім свідченням. Learning
Analyst фіксує спостережену поведінку, невизначеність і висновки за критеріями,
але не приймає рішення про подальшу траєкторію навчання на курсі або модулі.

## Політика використання ШІ

Для незалежності діагностики не проси ШІ створити готовий код, виправити його
або вигадати результати запуску. Документацію Python можна використовувати для
уточнення синтаксису після самостійної спроби; таке використання потрібно
коротко зазначити у здачі.
