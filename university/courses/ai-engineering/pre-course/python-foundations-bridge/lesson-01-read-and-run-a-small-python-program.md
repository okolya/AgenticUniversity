# Урок 01 — Читання та запуск малої Python-програми

## Мета уроку

Цей перший урок створює практичний міст до Python. Ти прочитаєш коротку
програму, поясниш її вхідні дані та результати виведення, запустиш її у
середовищі розробки, зробиш одну контрольовану зміну й перевіриш звичайний
результат та одну помилку через некоректні вхідні дані.

Це вступ до читання та виконання Python-коду, а не повний Python-курс і не
підсумкове оцінювання.

## Критерії успіху

Після цього уроку ти маєш уміти:

1. Визначити вхідні дані, результати виведення, значення даних, іменовані
   функції та порядок виконання програми.
2. Простими словами пояснити призначення малої Python-функції.
3. Зберегти приклад у `.py`-файлі та запустити його у середовищі розробки.
4. Зробити одну навмисну локальну зміну й до запуску описати її очікуваний
   ефект.
5. Зафіксувати звичайний результат і визначити загальну причину помилки через
   некоректні вхідні дані, не приховуючи та не підміняючи діагностичні дані.

Ці критерії дають формувальні свідчення для переходу від загального
програмування до інженерії та роботи в середовищі розробки. Вони не
підтверджують входження до модуля або опанування матеріалу.

## Основні ідеї

### Вхідні дані та результати виведення

**Вхідні дані** — це інформація, яку отримує програма. Вона може надходити від
користувача, з файла, аргументу командного рядка або іншого компонента.
**Результат виведення** — це інформація, яку програма повертає, друкує,
записує або передає іншому компоненту.

Для малої програми командного рядка `input()` є одним із можливих місць
отримання вхідних даних, а `print()` — одним із можливих місць виведення
результату.

### Значення даних і типи

Значення Python мають типи, які впливають на результат операцій. У прикладі
`"72"` — це текст, прочитаний із термінала, а `72` — ціле число після
перетворення. Перетворення може завершитися помилкою, якщо текст не є
коректним цілим числом.

У цій програмі `input()` завжди повертає текст. `int(raw_score)` намагається
перетворити цей текст на ціле число. Лише після успішного перетворення
`describe_score` отримує ціле число, а її результатом є текстова позначка.

### Іменовані функції

Функція надає групі кроків назву та межу відповідальності. Її параметри — це
вхідні дані функції, а значення, яке вона повертає, — її результат. Корисна
функція зазвичай виконує одну зрозумілу задачу.

### Порядок виконання

Порядок виконання визначає, які інструкції виконуються і в якій послідовності.
`if`, `elif` та `else` обирають між варіантами. Нижче функція спочатку перевіряє
діапазон, а потім обирає `label` — текстову позначку, що описує результат, —
на основі `threshold` — порогового значення, з яким порівнюють оцінку.

### Перехід від PHP

Якщо ти працював із PHP, використовуй цей досвід як допомогу для читання, а не
як доказ, що Python уже відомий. Урок навмисно використовує знайомі інженерні
ідеї — функції, параметри, значення, які повертаються, умовні конструкції,
введення та виведення, — але Python має власний синтаксис, правила відступів,
перетворення значень і поведінку під час виконання. Перевіряй кожну інструкцію
Python та кожен спостережений результат, а не перекладай код механічно з PHP.

## Малий оригінальний приклад

Створи файл `lesson01_score.py` і введи цей код:

```python
def describe_score(score):
    """Return a label for a score on a 0–100 scale."""
    if score < 0 or score > 100:
        raise ValueError("score must be between 0 and 100")

    if score >= 70:
        return "ready"
    return "keep practicing"


def main():
    raw_score = input("Enter a sample score from 0 to 100: ")
    score = int(raw_score)
    label = describe_score(score)
    print(f"Score {score}: {label}")


if __name__ == "__main__":
    main()
```

Дані навмисно вигадані й не містять облікових записів, даних клієнтів або
виробничої інформації.

### Очікуваний результат

Після запуску програма попросить ввести оцінку. Для введення `72` очікуй:

```text
Enter a sample score from 0 to 100: 72
Score 72: ready
```

Для введення `55` очікуй:

```text
Enter a sample score from 0 to 100: 55
Score 55: keep practicing
```

Для введення `seventy` виникне помилка перетворення під час `int(raw_score)`.
Для введення `120` виникне `ValueError` усередині `describe_score`. Це очікувана
поведінка прикладу, яку потрібно побачити та пояснити.

Прочитай програму зверху вниз:

1. `describe_score` — іменована функція. Вона отримує `score` і повертає
   `label`.
2. Перевірка діапазону захищає програму: значення поза заявленими межами
   викликають `ValueError`.
3. Другий `if` обирає рішення: оцінки від `70` повертають `"ready"`, інші
   коректні оцінки — `"keep practicing"`.
4. `main` читає текст, перетворює його на ціле число, викликає іменовану
   функцію та друкує результат.
5. Фінальна умовна конструкція запускає `main()`, коли файл виконується
   безпосередньо. Вона не запускає `main()` лише через імпорт файла.

Перед запуском файла спрогнозуй:

- Яке введення дасть `Score 72: ready`?
- Яке введення дасть `Score 55: keep practicing`?
- Яка операція може завершитися помилкою для введення `seventy`?
- Яка операція відхиляє `120`?

## Запуск і перевірка

Із каталогу, що містить файл, запусти:

```text
python lesson01_score.py
```

Якщо твоє середовище використовує `python3`, запусти:

```text
python3 lesson01_score.py
```

Виконай ці окремі запуски:

1. Введи `72` і зафіксуй звичайний результат.
2. Введи `55` і зафіксуй інший правильний варіант виконання.
3. Введи `seventy`. Перевір трасування помилки (`traceback`) і визнач, що
   `int(raw_score)` не може
   перетворити цей текст на ціле число.
4. Введи `120`. Перевір трасування помилки (`traceback`) і визнач, що
   `describe_score` відхиляє
   значення поза своїм оголошеним діапазоном.

Трасування помилки (`traceback`) — це діагностична інформація. Для цього уроку не приховуй його, не
замінюй вигаданим повідомленням і не вставляй конфіденційні відомості про
середовище у свої свідчення.

## Керована C0-практика — напиши зміну самостійно

Зроби одну контрольовану зміну у своїй локальній копії:

> Зміни порогове значення готовності з `70` на `80`.

Перед редагуванням запиши:

- точний рядок або значення, яке плануєш змінити;
- одне введення, чия текстова позначка має змінитися після редагування;
- одне введення, чия текстова позначка має залишитися незмінною;
- одне некоректне введення, яке все ще має завершитися помилкою.

Щоб порівняння було однозначним, використай такі перевірки:

- до зміни `75` дає `ready`, а після зміни порога на `80` має дати
  `keep practicing`;
- `55` має дати `keep practicing` і до, і після зміни;
- `110` має завершитися `ValueError` і до, і після зміни, бо це значення поза
  дозволеним діапазоном `0–100`.

Потім зміни лише порогове значення, запусти програму з цими введеннями та
порівняй спостережений результат зі своїм прогнозом. Після фіксації свідчень
віднови початкове порогове значення, якщо немає причини залишати змінену
копію.

### Межі використання ШІ та інструментів

Ти можеш використовувати редактор, інтерпретатор Python та офіційну
документацію Python, щоб зрозуміти синтаксис, `ValueError`, `input`, `int`,
`if` і `return`. Можна попросити ШІ пояснити повідомлення про помилку,
перевірити твоє розуміння поняття Python або запропонувати питання для
дослідження.

ШІ не має писати запитану зміну порогового значення, створювати готове
розв’язання замість тебе або вигадувати свідчення. Внеси зміну самостійно й
повідом команди та спостереження, які ти справді отримав. Не використовуй цю
практику як підсумкове рішення про опанування матеріалу.

## Мінімальні свідчення

Поверни лише:

- шлях до файлу та команду запуску;
- фактичний результат для `72`, `55` і одного некоректного значення;
- одним-двома реченнями пояснення, що роблять `main` і `describe_score` та як
  дані проходять через програму;
- короткий опис контрольованої зміни й одного спостереженого результату;
- одне питання або критика, якщо вони залишилися.

Не переписуй повний traceback, повну карту програми або весь запис термінала.
Приймаючий Worker сам перегляне файл і запустить його для перевірки звичайної
та помилкової поведінки. Для помилки достатньо назвати тип винятку й коротке
фінальне повідомлення. Якщо файл не запускається, вкажи коротко команду та
спостережену причину.
