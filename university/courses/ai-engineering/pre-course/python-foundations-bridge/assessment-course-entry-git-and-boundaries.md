# Course Entry — Git і межі конфігурації

> **Статус:** готовий до проведення. Learning Analyst завершив фінальну
> перевірку після педагогічного review Instructional Assistant.

## Призначення

Це наступна обмежена діагностика після Python diagnostic. Вона перевіряє два
ще непідтверджені критерії входу до AI Engineering Module 1:

- відмінність робочої зміни від збереженої Git-версії;
- відмінність коду, конфігурації та локальних секретів.

Послідовність має два практичні слоти. Після другого слота Learning Analyst передає
декану докази й невизначеність. Нові слоти не створюються автоматично.

## Слот 1 — робоча зміна та Git-версія

У приватній робочій папці створи окрему Git-робочу папку та поклади в неї
робочий файл `app.py`. Можна взяти перевірений Python-файл із попередньої
діагностики як початкову версію.

1. Створи початкову Git-версію.
2. Внеси одну невелику контрольовану зміну до `app.py`.
3. Запусти програму й перевір змінену поведінку.
4. Переглянь робочу зміну через `git diff`.
5. Збережи зміну окремою Git-версією.
6. Перевір, що після збереження робоча папка чиста через `git status`.

### Мінімальна здача слота 1

Поверни:

- шлях до Git-робочої папки та команди запуску й перевірки;
- короткий опис зміни;
- два ідентифікатори або повідомлення Git-версій;
- один короткий висновок: чим відрізнялися робоча зміна, `git diff` і
  збережена версія.

Не переписуй повний вивід Git або термінала.

## Слот 2 — код, конфігурація та локальний файл

У тій самій робочій папці:

1. Винеси одне змінне значення програми з `app.py` у `config.local.json`.
2. Додай `config.example.json` із тією самою структурою, але без приватних
   значень.
3. Додай `config.local.json` до `.gitignore`. Не додавай його до Git-версії.
4. Запусти програму з локальною конфігурацією.
5. Перевір Git-статус: `config.local.json` не має потрапляти до збереженої
   версії, а `config.example.json` має бути придатним для спільного коду.

Не використовуй справжні секрети. Для перевірки межі достатньо безпечного
умовного значення на кшталт `local-demo-token`.

### Мінімальна здача слота 2

Поверни:

- назви `app.py`, `config.example.json` і `config.local.json` та коротко їхню
  роль;
- команду запуску та фактичний результат;
- короткий результат перевірки Git-статусу;
- одне речення про те, чому локальний файл і секрет не належать до коду.

## Приймання

Learning Analyst сам переглядає робочу папку, запускає програму, перевіряє
Git-історію, `git diff`, `git status` і межі конфігураційних файлів. Опис
студента звіряється з фактичними файлами та командами. За потреби Analyst
просить одну малу контрольовану зміну або ставить одне коротке питання.

Після двох слотів Analyst повертає декану докази за критеріями. Цей документ
не підтверджує Course Entry і не відкриває Module 1 автоматично.
