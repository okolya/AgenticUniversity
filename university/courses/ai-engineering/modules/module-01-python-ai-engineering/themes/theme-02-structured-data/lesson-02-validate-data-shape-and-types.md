# Урок 2. Перевіряємо форму й типи даних

## Мета уроку

Після уроку студент уміє перевірити, що структуровані дані мають потрібні
поля, типи та допустимі значення, і повернути зрозумілу помилку для
некоректних даних.

## Що вже потрібно знати

Потрібно вміти читати JSON і діставати поля зі словника.

## Нові слова

- **Форма даних** — набір очікуваних полів та їхніх типів.
- **Обов'язкове поле** — поле, без якого дані не можна прийняти.
- **Обмеження значення** — правило для допустимого діапазону або набору
  значень.
- **Валідація** — перевірка даних перед їхнім подальшим використанням.

## Приклад перевірки

Для показника температури можна вимагати поле `temperature_c` з числовим
значенням від `-30` до `50`. Дані, у яких поле відсутнє, має текст замість
числа або містить `70`, не проходять перевірку.

Перевірка має повідомляти, яке правило порушено. Вона не повинна мовчки
замінювати неправильне значення на припустиме.

## Практичне завдання

Продовж роботу в папці:

`homeworks/ai-engineering/2026.09/module-01/theme-02/`

Додай до програми функцію:

```python
def validate_reading(reading):
    ...
```

Вона має перевіряти наявність полів `city`, `temperature_c` та `is_day`, типи
значень (`city` — текст, `temperature_c` — число, `is_day` — логічне значення)
і діапазон температури `-30...50`. Для кожного класу помилки поверни
або підніми зрозуміле повідомлення, але не виправляй вхідні дані мовчки.

Перевір щонайменше:

- правильний об'єкт;
- відсутнє поле `city`;
- текст замість числа в `temperature_c`;
- температуру `70`.

## Мінімальна здача

Поверни шлях до файла, команду запуску та короткий результат чотирьох
перевірок. Додай одне речення про різницю між відсутнім полем і неправильним
типом. Приймаючий працівник перегляне та запустить код.

## Критерії уроку

- форма даних описана явно;
- перевіряються поля, типи та діапазон;
- кожен обов'язковий недолік дає помітний результат;
- вхідні дані не змінюються мовчки.
