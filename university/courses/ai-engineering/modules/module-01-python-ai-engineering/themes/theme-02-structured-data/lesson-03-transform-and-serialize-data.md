# Урок 3. Перетворюємо та серіалізуємо валідні дані

## Мета уроку

Після уроку студент уміє перетворити лише валідний об'єкт у нове
представлення та зберегти його в JSON без втрати початкової структури.

## Новий результат і зв'язок

Lesson 3 споживає результат `validate_service()` з Lesson 2. Він додає
трансформацію та серіалізацію, але не змінює вхідний об'єкт і не записує
успішний результат для невалідних даних.

## Практичне завдання

Додай:

```python
def transform_service(service):
    ...


def save_service(service, output_path):
    ...
```

`transform_service()` має повернути новий словник із полем `status`:

- `available`, якщо `healthy` дорівнює `True` і `latency_ms` не перевищує `1000`;
- `degraded` в інших валідних випадках.

`save_service()` записує результат через `json.dump()` у
`service.output.json`. Основний pipeline має бути саме:

`read → validate → transform → serialize`.

Не змінюй `service.json`. Якщо валідація не пройшла, `service.output.json` не
повинен створюватися як успішний результат.

Перевір валідний об'єкт із `latency_ms: 120` і валідний об'єкт із
`latency_ms: 1400`. Перевір також один невалідний об'єкт.

## Мінімальна здача

Поверни шляхи вхідного та вихідного файлів, команду й короткі фактичні
результати. Одним реченням поясни, чому трансформація виконується лише після
валідації.

## Критерії

- pipeline має правильний порядок;
- вхідні поля збережені;
- `status` обчислюється за явним правилом;
- невалідні дані не серіалізуються як успішні.
