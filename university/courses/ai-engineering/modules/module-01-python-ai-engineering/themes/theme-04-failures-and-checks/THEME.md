# Theme 4 — Failures, focused checks, and debugging

- **Module:** Python AI Engineering
- **Owner:** assigned Engineering Faculty Lecturer
- **Status:** bounded four-Lesson sequence approved; detailed Lessons are authored just in time

## Boundary

Handle expected input, operational, and dependency failures deliberately;
validate behavior with focused checks; and correct observed defects. Do not
expand into large test frameworks or production observability.

## Theme outcome

The Student can reproduce a failure, make a bounded correction, and explain
what the checks establish and what they do not establish.

## Success criteria

- failure categories and useful diagnostics are distinguished;
- ordinary, boundary, and failure cases are checked;
- a correction is verified by rerunning the relevant case;
- no misleading successful output is produced after failure.

## Complete Lesson sequence

This Theme contains exactly four Lessons:

1. distinguish input, operational, and dependency failures;
2. write focused checks for ordinary, boundary, and failure behavior;
3. reproduce a defect, make a bounded correction, and verify the correction;
4. complete a bounded failure-handling component and return the Theme evidence.

## Theme checkpoint and stop condition

The final artifact must show a reproducible failure, a deliberate correction,
focused checks, and an explanation of what was not checked. After Lesson 4 the
Lecturer returns evidence to Dean; no fifth Lesson is created without a new
Dean decision. Large test frameworks and production observability remain out
of scope.

## Lecturer handoff

The Lecturer prepares these four Lessons only. Every practical task must be
run and inspected by the accepting Worker and must include only the evidence
needed for the stated criterion. The Lecturer returns the final Theme
evidence to Dean rather than extending the sequence.
