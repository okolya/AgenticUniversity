# Courses

Courses are public Faculty-owned academic structures.

A Course defines a stable direction, target competencies, prerequisites, Course Success Criteria, and a Module framework. It does not require every Module, theme, lesson, exercise, lab, or material to be authored in advance.

Canonical Course architecture is owned and approved by the appointed Dean under `university/policies/curriculum-authority.md` and `university/workflows/course-design.md`.

Current Courses:
- `ai-engineering/COURSE.md` — Engineering Faculty.

## Content ownership hierarchy

`Course (Dean) → Module (Dean) → Theme (Lecturer) → Lesson introducing new material (Lecturer)`

Teacher owns reinforcement/remediation sessions; Laboratory Specialist owns labs/practical activities; Learning Analyst independently measures; Examiner owns the final Module verdict. See `policies/learning-content-authority.md` and the Module/Theme/Lesson workflows.

## Module contracts

Each Module should become navigable before detailed content exists by defining a purpose, Entry Contract, Exit Contract, broad competency areas, and hard dependencies. Detailed Themes/Lessons/materials remain just-in-time. See `policies/module-contracts.md`.
